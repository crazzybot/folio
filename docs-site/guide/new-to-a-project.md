# Getting to know a project's docs

Joining a project, or picking one up again after a while? Its specs and
ADRs say what was decided and why, before the code shows how. Folio helps
you read your way in, without an agent and without changing a file.

## Start with what still holds

1. **Open the project's folder**, or its `docs/` folder, with **File → Open
   Folder…** (`⌘O` / `Ctrl+O`). To read only part of a large repository,
   [focus on a folder](./reading#focus-on-a-folder).
2. **Look at the statuses.** Each document's icon shows its
   [status](./reading#statuses-and-tags). Rejected, deprecated and
   superseded documents are dimmed: what's left is what applies today.
3. **Filter the list.** The funnel button lists only the `accepted` or
   `implemented` decisions, or only what's still `proposed`. A tag narrows
   it to one subject, such as every decision about retries.

## Follow the decisions

- **Links between documents work.** Click through to the spec an ADR
  refers to; Back returns you to where you were.
- **Follow the history.** A superseded ADR links to the one that replaced
  it.
- **Hover a document** in the list for its status, date, decision makers and
  tags. In a git repository, the hover card also shows the last commit that
  changed it.

## Find what you need

- **Search titles and headings** as you type in the search box, or the
  full text with `⇧⌘F` / `Ctrl+Shift+F`, when you meet a term you don't
  know. See [Search](./reading#search).
- **The outline** beside each document jumps to any section.

## Keep track as you read

- **Bookmark** the documents you'll come back to (`⌘D` / `Ctrl+D`).
- **Note your questions** on the passages they're about, and keep them
  with **Only me** if they're for you alone. Every note is in the
  [Marks view](./marking-up#the-marks-view).
- **See what changes.** Once you've read a document, Folio marks it when it
  changes, and names the sections that changed. See
  [New and changed documents](./reading#new-and-changed-documents).
